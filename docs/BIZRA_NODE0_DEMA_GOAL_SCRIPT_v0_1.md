## Why Node0 exists

BIZRA Node0 exists to prove the whole BIZRA vision in its smallest
living form: **one human, one sovereign node, one real task, one
complete proof lifecycle**.

Node0 is not a demo, not a pitch, and not an incomplete prototype. It is
the **first seed**. A seed does not contain the tree at full size, but
it contains the complete DNA of the tree. In the same way, Node0 must
contain the complete DNA of BIZRA: human sovereignty, DEMA, PAT, SAT,
FATE, consent, evidence, receipts, memory, local resources,
proof-of-impact logic, quality gates, refusal discipline, and
self-improvement.

DEMA is the face, cockpit, and safety membrane of Node0. DEMA helps the
human see the system state, understand what is live, what is planned,
what is blocked, what proof exists, and what the next safe action is.
DEMA may preview, explain, guide, and request consent. DEMA must not
silently execute, overclaim, mint, federate, or replace the human.

## BIZRA as a Living, Dynamic, Cultivated System

BIZRA should not be understood as a static application or a fixed platform.

BIZRA is a living, dynamic system.

It begins like a seed. The first seed contains the initial DNA: proof, consent, memory, ethics, agents, receipts, and the ability to learn from verified experience. But the seed is only the beginning.

As BIZRA receives more knowledge, more data, more missions, more feedback, and more proof receipts, it grows. It develops roots through its proof spine, a trunk through its core architecture, branches through agents and workflows, and fruit through useful outcomes, products, insights, and value creation.

This means BIZRA is not merely built once. It is cultivated.

Each verified interaction becomes part of its memory. Each refusal teaches its boundaries. Each successful mission strengthens its patterns. Each audit improves its integrity. Each new dataset, agent, and protocol adds another growth ring to the system.

The goal is not to create a static machine.

The goal is to grow a proof-governed, ethically grounded, self-improving intelligence ecosystem — one that evolves with discipline, consent, and Ihsān.

We have not completed the tree.

We have planted the first seed.

## Operating law

> **State before screen.**
> **Contract before runtime.**
> **Consent before capability.**
> **Evidence before trust.**
> **Node0 before mesh.**

These five lines bind every Node0/Dema decision. Any change that would
loosen them requires an ADR and an operator-typed GO.

## Mission lifecycle

The goal is to make Node0 an A+ local-first, proof-bound, self-sustaining
AI homebase where every mission follows a complete lifecycle:

**intention → task capsule → PAT proposal → SAT verification → FATE gate
→ human consent → bounded execution → tests/evals → receipt → memory
update → roadmap update → next safe action.**

The role of each named subsystem:

- **PAT** serves the human as the private reasoning and execution team.
- **SAT** serves the system as the verifier and guardian.
- **FATE** protects the boundary between intention and capability via
  exact-string consent.
- **EvidenceChain** preserves what happened.
- **Receipts** make action inspectable.
- **URP** begins as local resource awareness and later becomes the shared
  soil of the forest. URP is **not live** as a shared lane today; only
  the local-awareness portion is `MEASURED`.
- **Proof-of-Impact** begins as evidence-bound local scoring, **not** as a
  public economic claim. PoI rewards are **not live**.

Node0 must be powerful, but restrained. It must be useful, but honest.
It must be ambitious, but truth-labeled. It must show the future without
pretending the future is already live.

## A+ quality definition

A+ quality means:

- clean architecture and clear module boundaries
- no hidden autonomy or secret execution
- no local path, secret, or private data leakage
- deterministic tests and regression gates
- public-safe proof artifacts
- visible current limits
- clear first-run experience
- strong error handling and failure classification
- docs that match reality
- every claim tied to evidence
- every risky action gated by exact consent
- every completed mission preserved by receipt

Each of these maps to one or more `MEASURED` rows in
[`CURRENT_LIMITS.md`](CURRENT_LIMITS.md). When a row is below `MEASURED`,
A+ has not been reached for that dimension yet — name the gap, do not
hide it.

## Flagship test

Node0 becomes the flagship when a new person can inspect it and
understand, in under thirty minutes:

- what BIZRA is,
- what DEMA does,
- what is live,
- what is not live,
- what proof exists,
- what is blocked,
- and what safe action comes next.

If any of those seven questions cannot be answered from the local repo +
`docs/CURRENT_LIMITS.md` + `docs/PRODUCT.md` + `dema status / first-run /
roadmap dev / doctor`, that is the gap to close next.
