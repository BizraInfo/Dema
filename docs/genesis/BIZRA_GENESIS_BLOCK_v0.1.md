## 3. What BIZRA Is

BIZRA is a candidate sovereign-agent infrastructure pattern: one human, one
local node, one consent boundary, one receipt chain, and one designed path
toward a shared URP substrate.

Proof-safe public wording:

```text
BIZRA aims to make agentic infrastructure proof-native, consent-bound, and
impact-governed.
```

Forbidden public wording:

- "BIZRA is already Web4."
- "The BIZRA public network is live."
- "BIZRA has launched a token economy."
- "BIZRA guarantees rewards, yield, or investment return."

The category thesis may be described as a candidate Web4 architecture only when
paired with the current proof boundary.

## 4. Why Node0 Exists

Node0 is the first living proof path for the seed pattern. It must prove that a
single local node can stand before the network opens.

Node0 exists to prove:

1. A human remains the only legal mutator.
2. Dema can show local state without pretending to be the whole system.
3. Consequential actions require exact-string consent.
4. Receipts remain the trust substrate.
5. Governance gates can refuse before scale.
6. Network expansion waits for closed-loop proof.

Node0 does not prove the future forest by itself. It creates the floor another
human can inspect, reject, extend, or improve.

- claim public URP is live.

## 6. What URP Is

URP is the designed shared substrate where nodes eventually contribute resources
and consume capabilities under governance. In current Dema truth labels, public
URP remains `DESIGNED_NOT_LIVE`.

The repo currently contains local URP-related preview and declaration surfaces,
including local index flows and the Node0 5 SAT launch/lock declaration. These
are not the same as a live public URP runtime.

## 7. What the 5SAT Lock Proves

The current Node0 5 SAT lock proves a local declaration can be built, verified,
and exercised through Dema with exact consent. It declares exactly five SAT
profiles and records a lock posture for the Dema face.

It does not prove:

- a running SAT daemon,
- production manipulation prevention,
- a live shared URP,
- Node1 connection,
- federation,
- token minting,
- Proof-of-Impact reward eligibility.

The lock is a necessary Genesis ingredient because it names the governance
shape Node0 must later enforce at runtime.

## 8. What Covenant Gate Blocks

Covenant Gate v0.1 is a prototype consent-and-screening gate. It makes one
important rule concrete:

```text
Agents may analyze, propose, screen, simulate, and prepare.
Agents must not silently approve, deploy, migrate liquidity, or move funds.
```

At v0.1 it blocks overreach at the proposal layer. It is not production
cryptography, not legal advice, not Shariah certification, and not a deployed
financial gate.

## 9. Proof-before-Mint Covenant

Genesis Block adopts this ordering:

```text
Build value -> prove impact -> write receipt -> review eligibility -> only then
consider any future reward or mint mechanism.
```

At v0.1:

- no premint is declared,
- no public token claim is allowed,
- no economic return is promised,
- no reward eligibility exists without a future verified Proof-of-Impact
  receipt chain.

This preserves the ethical sequence: proof first, trust second, scale third.

## 12. What Must Be Proven Before Node1

Node1 stays held until Node0 proves the closed loop:

1. Node0 identity and local state are inspectable from disk.
2. Dema can boot, show status, draft a mission, draft consent, and list receipts.
3. Node0 5SAT lock is reproducible from clean state.
4. Covenant Gate screens at least one local proposal and records the decision.
5. A bounded mission produces a receipt or proof-safe preview under exact
   consent.
6. The receipt chain can be listed and read.
7. Local performance and QA gates are green.
8. Public bridge specification exists with capability, permission, identity,
   rate-limit, quarantine, and receipt requirements.
9. Node1 handshake protocol exists with connect, approve, log, revoke, and
   disconnect paths.
10. Claim Register language is updated before any public network statement.
