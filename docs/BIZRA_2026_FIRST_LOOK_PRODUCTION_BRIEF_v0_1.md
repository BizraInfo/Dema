# BIZRA 2026 First Look Production Brief v0.1

> "Canon defines truth. Narrative defines story. Production brief defines expression. Media generation comes only after expression is bounded."

## 1. Purpose

This document is the **expression-layer brief** between the eight-pillar canon and any media artifact (Canva slide, video frame, landing page, social teaser, visual emulator screen, lighthouse invitation, founder-story piece).

It exists so that any future contributor — designer, animator, narrator, copywriter, video producer, web builder, social poster — can transform the canonical text into a public artifact **without breaking truth**. Every prompt, every visual instruction, every wording block in this brief inherits from a specific row in the canon and carries a specific truth label.

This brief does **not** produce assets. It produces the **instructions** that any future asset-producing slice must obey.

## 2. Truth Label

```text
DECLARED_BIZRA_2026_FIRST_LOOK_PRODUCTION_BRIEF_v0_1
```

This label means the asset-family briefs (§6-12), the matrices (§13-14), the forbidden lists (§15-16), the truth-label requirements (§17), and the three prompt packs (§19-21) are **declared** and consistent with the eight-pillar canon as of 2026-05-21. No artifact derived from this brief is automatically public-ready — every artifact must run the Production Checklist (§22) and the Review Gate (§23) before leaving Node0.

## 6. First-Look Video Brief

**Purpose**: a 60-180 second cinematic piece carrying the 7-scene narrative arc from `BIZRA_2026_FIRST_LOOK_NARRATIVE_v0_1.md` §11-17.

**Length tiers**: 30s teaser (Scene 0 + Scene 6 only) · 90s first-look (all 7 scenes compressed) · 3-minute founder-proof (all 7 scenes + extended Scene 3).

**Visual mood**: cinematic, contemplative, scaled-to-human. No Silicon-Valley quick-cuts. No urgency manufactured by edit pace.

**Voice direction**: per First Look §23 — calm, reflective. End with choice, never with CTA-button.

**On-screen text**: the six canonical lines from First Look §24 may appear as captions; no other on-screen text without explicit canon support.

**Mandatory closing**: the question *"What will you choose?"* (verbatim from Origin Video 001 transcript).

**Source-block to use**: First Look §25 (one of three Public Wording Blocks, depending on length).

**Forbidden**: any video frame showing a "live" forest, a token UI, a node-network heatmap presented as deployed, a price chart, an APY chart, a "Buy now" CTA. Any closing without the choice element.

**Purpose**: static visuals for social, founder-story, lighthouse invitation, and deck use.

- 1:1 square post (Instagram, LinkedIn)
- 9:16 vertical post (Instagram story, TikTok, YouTube short still)

- 4:5 carousel slide

**Required truth label on any asset that touches a `DESIGNED_NOT_LIVE` element**: visible caption "designed, not live" or "scenario" — Production Checklist §22 enforces this.

**Forbidden**: any asset showing the token economy, URP marketplace, UKE shared memory, PoI rewards, or scale projections **without** the on-screen qualifier. Any asset that omits the choice framing in its closing slide of a series.

## 8. Visual Emulator Brief

**Purpose**: a sandboxed visual that lets a viewer see Node0 + future-forest behavior without a live network. Reference: First Look §26 + Component DNA Layer 18.

**Mandatory separation rule**: every emulator screen must visually distinguish four bands by truth label:

| Band | What it shows | Required on-screen label |
|---|---|---|
| **Verified now** | Single Node0, single human, hash-bound artifacts, current 156-repo footprint | `VERIFIED` (or no label needed — it's the floor) |
| **Pilot stage (planned)** | 5-node demo (the Lighthouse pilot) | `DESIGNED_NOT_LIVE` or `PILOT_PROJECTION` |
| **Forest scenarios** | 1M / 100M / 1B node visualizations | `SCENARIO` with named assumption set (node count, uptime, sharing rate) |
| **Architecture overlay** | PAT-7 / SAT-5 / UKE / URP layer diagram | `DESIGNED_NOT_LIVE` on every layer label |

**Forbidden**: showing a 1M-node visual without the `SCENARIO` caption; showing PAT/SAT/UKE/URP without the design-only qualifier; showing any token icon as "tradable" or "redeemable".

**Required**: any user-interactive emulator must include an "evidence panel" that names the canon doc + section behind every visible claim.

## 10. Social Teaser Brief

**Purpose**: short-format hooks that lead to the website / landing / video — not standalone product pitches.

**Platforms in scope**: X (Twitter), LinkedIn, Instagram, TikTok (text overlay only — no live token / financial overlay), YouTube Shorts.

## 11. Private Lighthouse Invitation Brief

**Purpose**: the artifact handed (privately) to a vetted external operator who is being invited to run a Node0 on their own machine as a Lighthouse pilot participant.

**Audience**: single human, known to the founder, who has agreed in principle to operate their own Node0 under the same discipline (PAT/SAT/EffectCap/receipts).

**Form**: PDF + short video. PDF inherits Founder Proof §26 + First Look §25.2 (90s first-look). Video may reuse the First-Look Video.

**Required content**:
- The Lighthouse pilot's named scope (single operator, single Node0, single machine).
- The consent + receipt boundary (every action is operator-typed; every state mutation has a receipt).
- The forbidden language list (this prevents the pilot operator from making external claims that outrun the canon).
- The verification path (how the pilot operator can inspect their own receipts, run the same gates, verify nothing is hidden).
- A typed-consent block for the operator to enter their explicit "GO" before installing.

**Forbidden**: any framing of the pilot as a "token allocation event", a "founders' round", an "early access program with rewards", or any economic framing. The pilot is **operator discipline**, not a product.

## 12. Founder Story Brief

**Purpose**: the long-form piece (text, audio, or video) telling the human story behind BIZRA without crossing into founder worship.

**Audience**: a reader/listener seeking the human story, not the product pitch.

**Required structure** (inherits Founder Proof §11-17):
1. The eternal question (Origin Video 001 opening)
2. The Arabic root papers (with Drive screenshot witness + hash-bound bizra.pdf identity)

**Forbidden numbers as `VERIFIED`** in v0.1: 15k+ hours · 600 GB+ R&D · 5k+ AI conversations · 3 years on GitHub · any exact Ramadan-2023 start / June-2023 completion date.

**Forbidden framings**: "the visionary", "the genius", "the only one in the world", "the future is here because of one person". Use the bounded language from Founder Proof §17.

## 22. Production Checklist

- [ ] The asset's metadata file (per §17) is complete and saved alongside the asset.
- [ ] Every claim traces to a row in §18 / First Look §18 Evidence Anchor Map.
- [ ] No claim is labeled `VERIFIED` if its underlying canon row carries `DERIVED`, `OPERATOR_ATTESTED`, or `SOURCE_PENDING`.
- [ ] No phrase from §16 (Forbidden Wording) appears in the asset (text, captions, alt-text, audio).
- [ ] No visual from §15 (Forbidden Visuals) appears in the asset.
- [ ] Any `DESIGNED_NOT_LIVE` element carries the visible "designed, not live" qualifier on-screen.
- [ ] Any `SCENARIO` element carries the visible "scenario" / "projection" caption with its assumption set named.
- [ ] The closing beat includes the *choice* framing if the asset is narrative-shaped.
- [ ] The Arabic text for `الرسالة` and `البذرة` (if used) is reproduced verbatim — not transliterated as substitute.
- [ ] If the asset cites a number from Founder Proof §11 (GitHub) or §12 (local corpus), the citation matches the canon exactly.
- [ ] No CTA-button-only close; choice framing or typed-consent flow is present where action is requested.
- [ ] The First Look §29 Verification Checklist has been applied (this checklist is a superset, not a replacement).
- [ ] The operator has typed explicit consent for the asset to ship externally.

A produced asset that fails any item is revised or held; never shipped with an unchecked box.

## 23. Review Gate

Before publication, the asset passes through this gate:

1. **Producer self-review** — Production Checklist (§22) signed off.
2. **Canon cross-check** — every claim row in the asset's metadata matches a current row in the eight pillars (no drift since the eight-pillar canon was published).
3. **First Look §29 Verification Checklist** — applied independently.
4. **Operator typed consent** — exact string per ADR-005, with timestamp.
5. **Asset Receipt drafted** — a release receipt per Delivery Spine §24 template, scoped to the asset (`bizra.dema.asset_release_receipt.v0.1`).
6. **If asset is for external audience** — second reviewer (operator or trusted lighthouse pilot operator) confirms the Forbidden lists (§15, §16) before publication.
7. **If asset claims any number or date** — the citation matches the canon to the character.
8. **If asset touches token / economy / Sharia / scale-claim language** — automatic hold; must escalate to canon-level review.

The gate is **sequential**. An asset that fails any step is revised or held.
